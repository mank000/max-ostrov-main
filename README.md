# Остров — досуг и общение внутри MAX

Мы, команда из четырёх человек, развиваем «Остров» как мини-приложение MAX: здесь можно найти мероприятие в своём городе, собрать компанию, общаться с друзьями и делиться впечатлениями. У пользователя один аккаунт MAX и один профиль для всех разделов.

## Доступ к работающему решению

- [Бот MAX](https://max.ru/t119_hakaton_max_bot): откройте его и запустите мини-приложение из карточки.
- [Адрес мини-приложения](https://kutezh-social.ru/) и [API](https://kutezh-social.ru/api/v1/health). Личные разделы открываются после входа из MAX.

Локальные контейнеры воспроизводят приложение, но не заменяют работающую версию в MAX. Для личного сценария нужны действующий бот и подписанные данные запуска MAX.

## Основной пользовательский сценарий

1. Откройте бота в MAX и запустите «Остров».
2. При первом входе заполните общий профиль и выберите город. При повторном входе регистрация не повторяется.
3. На телефоне выберите социальную часть. На компьютере сразу открывается лента, а разделы доступны в боковой навигации.
4. Откройте мероприятия или карту, найдите событие, изучите место и время, отметьте участие или сохраните его.
5. Откройте ленту, опубликуйте запись или отреагируйте на запись другого участника. Успешные действия отражаются в интерфейсе без повторного входа.

Дополнительно доступны друзья, уведомления, видео, мини-игры и знакомства. Для знакомств действуют отдельные возрастные правила; они не нужны для проверки основного сценария мероприятий.

## Состав и архитектура

| Компонент            | Назначение                                                 | Исходники                                         |
| -------------------- | ---------------------------------------------------------- | ------------------------------------------------- |
| Mini App             | React, TypeScript, Vite; экраны и встроенные разделы       | `frontend/`, `games/src/`, `dating/frontend/src/` |
| API                  | Go; MAX-вход, профиль, события, лента, медиа и уведомления | `backend/`, `dating/backend/`                     |
| Данные               | PostgreSQL; миграции применяются API при запуске           | `backend/internal/postgres/migrations/`           |
| Файлы                | Пользовательские загрузки в постоянном томе                | `KUTEZH_MEDIA_DIR`                                |
| Локальный веб-сервер | Nginx отдаёт Mini App и проксирует `/api/v1/`              | `frontend/docker-nginx.conf`                      |

API — один сервер с доменными модулями. Профиль, сессия и идентификатор пользователя общие для разделов. Сервер проверяет права и возрастные ограничения. Внутренний сайт модерации из `moderation/` не нужен для основного пользовательского сценария. Рабочую инфраструктуру описывает `docs/INFRASTRUCTURE.md`.

## Запуск всех локальных компонентов одной командой

Требуются Docker Engine и Docker Compose. Из корня репозитория:

```sh
docker compose up --build -d
```

Команда собирает Go API и Mini App из исходников, создаёт пустую PostgreSQL и запускает три компонента. Mini App: `http://localhost:8088/`; API: `curl http://localhost:8088/api/v1/health`. Первоначальная загрузка базовых образов зависит от канала связи и не входит во время сборки. Повторная сборка использует кеш Go и npm.

### Параметры окружения и порты

Для локального запуска `.env` не обязателен. Чтобы изменить настройки, скопируйте `.env.example` в `.env` и заполните локально. Compose читает `.env`; заполненный файл не следует отправлять в Git.

| Переменная                                  | Значение в Compose                       | Назначение                                                    |
| ------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------- |
| `WEB_PORT`                                  | `8088`                                   | Внешний порт Mini App и API-прокси                            |
| `POSTGRES_PASSWORD`                         | `local-only-password`                    | Пароль только локальной БД; для общего сервера задайте свой   |
| `KUTEZH_BOT_TOKEN`                          | пусто                                    | Токен своего бота MAX для реального входа и функций бота      |
| `KUTEZH_HTTP_ADDR`                          | `0.0.0.0:8080`                           | Адрес API внутри сети Compose                                 |
| `KUTEZH_DATABASE_URL`                       | формируется Compose                      | Подключение API к контейнеру `db`                             |
| `KUTEZH_MEDIA_DIR`                          | `/data/media`                            | Постоянное хранение медиа                                     |
| `KUTEZH_SESSION_COOKIE_SECURE`              | `false`                                  | Только для локального HTTP; для публичного HTTPS нужно `true` |
| `KUTEZH_TEXT_AI_MODE`                       | `off`                                    | Локальный режим без внешней проверки текста                   |
| `KUTEZH_MEDIA_X_ACCEL`                      | `false`                                  | Отдача медиа через API в локальном Nginx                      |
| `KUTEZH_GEOCODING_URL`                      | публичный Nominatim                      | Адрес геокодера                                               |
| `KUTEZH_IMAGE_AI_URL`, `KUTEZH_FACE_AI_URL` | локальные адреса без запущенных сервисов | Адреса внутренних проверок для расширенного сценария          |

Снаружи опубликован только `WEB_PORT`. Внутренние порты: API `8080`, PostgreSQL `5432`, Nginx `80`. Рабочий сервер использует отдельные HTTPS-настройки и приватное окружение.

### Зависимости и внешние интеграции

- Версии библиотек Go закреплены в `backend/go.mod` и `backend/go.sum`; клиентских пакетов — в `frontend/package-lock.json`. У других исходных разделов есть собственные lock-файлы.
- В API-контейнере установлен `ffmpeg` для обработки видео.
- MAX предоставляет подписанные данные запуска, вход и переходы в чаты. Для локальной проверки полного сценария нужен тестовый бот с доступным по HTTPS Mini App URL и его токен в `KUTEZH_BOT_TOKEN`. Для штатной проверки используйте действующего бота выше.
- Геопоиск использует внешний геокодер OpenStreetMap/Nominatim. При необходимости адрес меняется через `KUTEZH_GEOCODING_URL`; публичный Nominatim не используется для автодополнения.
- Расширенная проверка загруженного контента и подтверждение возраста в рабочем окружении используют отдельные внутренние сервисы. Они не входят в локальный Compose; текстовый сценарий мероприятий доступен без них. Для расширенного сценария укажите их адреса в `KUTEZH_IMAGE_AI_URL` и `KUTEZH_FACE_AI_URL`.

## Работа с данными и тестовые данные

PostgreSQL хранит профили, связи, мероприятия, публикации, действия и сессии. Медиа находятся в томе `kutezh_media`. При первом запуске API применяет миграции к пустой БД. Данные сохраняются при `docker compose down` и повторном `up`. `docker compose down -v` удаляет оба локальных тома и все данные в них.

В Git нет реальных аккаунтов, приватных дампов и рабочих ключей. `test-data.json` содержит безопасные входные значения и ожидаемые признаки ответов. Аккаунт создаётся через MAX; отдельного логина и пароля в «Кутеже» нет. Для проверки защищённых API используйте выделенный тестовый аккаунт MAX и передайте проверяющим его краткоживущую сессию отдельно от репозитория.

### Пошаговая проверка и ожидаемое поведение

1. Запустите `docker compose up --build -d` и дождитесь `healthy` у `db` и `api`: `docker compose ps`.
2. `curl -i http://localhost:8088/api/v1/health` → `200`, `{"status":"ok"}`.
3. `curl -i http://localhost:8088/api/v1/geocoding/config` → `200`, JSON с `autocomplete: false`.
4. `curl -i http://localhost:8088/api/v1/auth/session` и `curl -i http://localhost:8088/api/v1/events` без сессии → `401` и `error.code`; профиль и лента также закрыты без входа. После регистрации `GET /api/v1/events` возвращает `200` и поле `events` (на пустой БД — пустой массив).
5. Откройте [бота MAX](https://max.ru/t119_hakaton_max_bot), завершите регистрацию или войдите под существующим профилем. Проверьте выбор раздела, поиск мероприятия, его карточку и изменение участия/сохранения. Затем проверьте реакцию или комментарий в ленте.
6. Для API с выделенным аккаунтом используйте `openapi.yaml` и `DATA-API.yaml`; защищённые запросы передают `Authorization: Bearer <тестовый_токен>`.

Повторный вход не создаёт второй профиль; прямой вход в сервис до регистрации закрыт; успешные действия обновляют текущий экран. Пустая локальная БД не содержит мероприятий: создайте тестовое событие через интерфейс после MAX-входа или проверяйте работающее приложение.

### Известные ограничения

- Полный локальный сценарий требует MAX и публичный HTTPS URL Mini App. Обычный браузер на `localhost` не выдаёт подписанные данные MAX.
- Пустой локальный запуск не содержит пользователей и мероприятий; рабочие токены выдаются проверяющим вне публичного репозитория.
- Без внутренних сервисов часть операций с медиа и подтверждением возраста локально недоступна.
- Карта и геопоиск зависят от доступности внешних картографических данных.

## Остановка и повторный запуск

```sh
docker compose down
docker compose up -d
```

После изменения исходников: `docker compose up --build -d`. Состояние: `docker compose ps`; логи: `docker compose logs --tail=100 api web db`. `docker compose down -v` используйте только для осознанного удаления локальных тестовых данных.

## API и документы

Публичный HTTPS API: `https://kutezh-social.ru/api/v1`. `openapi.yaml` описывает методы основного сценария и форматы; `DATA-API.yaml` задаёт автоматические проверки по схеме 1.0; `test-data.json` хранит тестовые значения. Все маршруты находятся в `backend/internal/httpapi/routes.go`, маршруты знакомств — в `dating/backend/`. Продуктовые границы: `docs/PRODUCT.md`, `docs/ARCHITECTURE.md`, `docs/SERVICES.md`; правила работы: `AGENTS.md`.
